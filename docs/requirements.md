# BookHaven — требования и роли

Статус: **черновик, согласован частично** (решения ниже подтверждены владельцем; открытые вопросы отмечены).

## 1. Цель
Сайт-библиотека на русском языке: каталог книг, чтение, отзывы и оценки, профиль. Разделение на роли «Пользователь» и «Администратор». Сайт остаётся статическим (один `index.html`), данные хранятся в бэкенде Supabase.

## 2. Роли и доступ

| Что | Гость (без входа) | Пользователь | Администратор |
|---|---|---|---|
| Видеть сайт | нет (нужен вход) | да | да |
| Читать книги (читалка, Google Книги) | нет | да | да |
| Видеть отзывы и оценки других | нет | да | да |
| Писать отзывы и ставить оценки | нет | да (свои) | да |
| Редактировать и удалять **свои** отзывы | нет | да | да |
| Редактировать свой профиль | нет | да | да |
| Загружать свои тексты | нет | да | да |
| Редактировать каталог книг и описания | нет | нет | да |
| Удалять и редактировать **чужие** отзывы | нет | нет | да |
| Просматривать и удалять тексты пользователей | нет | нет | да |
| Назначать и снимать роль администратора | нет | нет | да |
| Статистика | нет | открытый вопрос | да |

**Правило безопасности:** роли проверяются только на сервере (правила доступа Supabase, RLS). Проверки в JavaScript — только для удобства интерфейса, они не защищают данные.

## 3. Сценарии использования и критерии приёмки

**С1. Регистрация.** Гость вводит почту, пароль, имя → получает аккаунт с ролью `user`.
- Критерий: после регистрации виден каталог; роль в базе = `user`; пользователь не может сам поставить себе роль `admin` (проверка запросом от имени пользователя).

**С2. Вход и выход.** Вход по почте и паролю; выход очищает сессию.
- Критерий: без входа каталог не виден ни в одном разделе; после выхода данные пользователя недоступны.

**С3. Оставить отзыв и оценку.** Пользователь выбирает книгу, оценку 1–5 и пишет текст.
- Критерий: отзыв виден всем пользователям; средняя оценка на карточке пересчитывается.
- Открытый вопрос: один отзыв на книгу на пользователя (рекомендация) или несколько.

**С4. Редактировать и удалить свой отзыв.**
- Критерий: изменение обновляет дату «изменено»; другой пользователь не может изменить или удалить чужой отзыв (проверяется запросом).

**С5. Смотреть отзывы других.** Открывается окно отзывов со всеми отзывами книги.
- Критерий: имя автора и его аватар видны; приватные поля профиля (о себе, цель) не видны другим.

**С6. Редактировать профиль.** Имя, о себе, аватар или фото, цвет, жанры, любимая книга, цель по чтению.
- Критерий: изменения сохраняются на сервере и доступны после входа с другого устройства.

**С7. Читать книгу.** «Читать» открывает внешний сайт (Google Книги) для обычных книг и читалку для загруженных текстов.
- Критерий: сохранённый прогресс чтения (позиция) привязан к аккаунту.

**С8. Загрузить свой текст.** Файл (txt, fb2, epub, docx, odt, rtf, html, md) загружается в хранилище аккаунта.
- Критерий: текст виден только владельцу и администратору; можно удалить свой текст.

**С9. Администратор редактирует каталог.** Добавляет, меняет и удаляет книги и описания.
- Критерий: изменение сразу видно пользователям; удаление книги не удаляет отзывы без подтверждения.

**С10. Модерация.** Администратор удаляет или редактирует чужие отзывы и тексты.
- Критерий: действие записывается (кто и когда).

**С11. Назначение ролей.** Администратор назначает роль `admin` другому пользователю.
- Критерий: только администратор может менять роли; администратор не может снять роль сам у себя, если он последний.

## 4. Модель данных (черновик)

- **profiles** — `id` (ссылка на аккаунт), `name`, `avatar`, `color`, `photo` (ссылка на файл), `genres`, `fav_book`, `goal`, `about` (видно только владельцу), `role` (`user` или `admin`), `created_at`.
- **books** — `id`, `title` (уникальный), `author`, `genre`, `pages`, `description`. Отзывы сейчас привязаны к названию книги; при переходе будет `book_id`, а старые названия сохранятся в поле `title`.
- **reviews** — `id`, `book_id`, `user_id`, `rating` (1–5), `text`, `created_at`, `updated_at`.
- **user_texts** — `id`, `book_id` (необязательно), `user_id`, `title` (уникально для пользователя), `file_path` (файл в хранилище `user-texts`), `words`.
- **visits** — `id`, `user_id`, `created_at` (одна запись на каждое открытие сайта вошедшим пользователем).
- **read_progress** — `user_id`, `book_id`, позиция, `updated_at` (таблица создана; позиция чтения пока не сохраняется).
- **read_list** — `user_id`, `book_id`, `read_at` (для счётчика «прочитано»).

## 5. Данные, которые уже есть в браузерах

Локальные данные (`bookComments`, `bookProfile`, `bookhavenReadList`, тексты в IndexedDB) **не переносятся автоматически**. Перенос — отдельный шаг, по отдельной просьбе владельца. Тексты пользователей при переносе сохраняются только если владелец это подтвердит.

## 6. Этапы работы

1. **Supabase:** проект, схема таблиц, правила доступа (RLS), первый администратор назначается вручную в базе. Проверка: тесты с двумя аккаунтами (пользователь и администратор).
2. **Вход и регистрация:** экраны входа и регистрации в стиле сайта, блокировка каталога для гостя.
3. **Отзывы и оценки:** общее хранилище, редактирование и удаление своих отзывов, просмотр чужих.
4. **Профиль на сервере.**
5. **Панель администратора:** каталог, модерация, роли.
6. **Тексты пользователей** в хранилище Supabase.
7. **Статистика** из базы (по решению владельца).
8. **Итоговая проверка** по всем сценариям выше и обновление этого документа.

## 7. Открытые вопросы
1. Один отзыв на книгу на пользователя или несколько? — **принято: один, его можно редактировать** (по рекомендации).
2. Кто видит статистику? — **принято: только администратор** (по рекомендации, владелец не ответил).
3. Первый администратор — **принято: вручную в базе** (по рекомендации). Владельцу роль ещё не назначена.
4. Нужна ли подтверждение почты при регистрации?
5. Удаление аккаунта — **не реализовано**. «Удалить профиль» очищает профиль, но не сам аккаунт и не отзывы.
